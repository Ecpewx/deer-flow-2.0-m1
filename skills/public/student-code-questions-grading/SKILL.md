# 学生编程题批改技能（双层混合模型）

## 技能定位

本技能用于**批改**研究生或高阶课程中的**编程题 / 算法实现**类提交（源代码或片段），输出维度化评分与可执行改进建议。评价策略为：

- **第一层（骨架）**：固定的**高阶元维度 + 权重锚点**，保证不同提交之间可比。  
- **第二层（血肉）**：结合本题题干、约束与（若有）样例，生成**动态查证要点**（如边界数据、复杂度要求、隐蔽缺陷）；**禁止**写成「命中某关键词即得分」的机械表。

---

## 最高优先级：批改时的 read_file 硬规则（本节约束高于下文一切说明）

当用户任务为**批改 / 评分 / 打分**学生**编程题、代码作业、算法实现**时：

1. **允许读取的唯一技能文件路径**（二选一，以实际为准）：  
   - 固定路径：`/mnt/skills/public/student-code-questions-grading/SKILL.md`  
   - 或：系统提示「技能列表」里 **name 恰好为 `student-code-questions-grading`** 的那一条所给出的 **location** 路径。  
2. **明确禁止**为完成本批改而 `read_file`：任何其他技能目录下的 `SKILL.md`。  
   唯一例外：当任务是“基于上一版的教师反馈重批”时，可额外读取 `student-grading-feedback-revision/SKILL.md` 一次。  
3. **禁止**用 `glob` / `grep` 在 `/mnt/skills/public/` 下以「code」「grading」「编程」等关键词**扫目录挑文件**；**至多** `read_file` 一次本技能正文，然后依据用户消息中的题目、代码与约束产出批改。  
4. **运行代码**：若当前环境**未**提供题目要求的可执行测试或用户未给出可复现运行输出，则**不得捏造**「已通过某组测试」；应写明依据为**静态阅读推断**，并在摘要或证据缺口中标注。若用户粘贴了运行结果或评测日志，则可引用。  
5. 若已误读其它文件：最终输出前须**忽略**其内容，仅按本文件与用户消息组织结论。

---

## 最高优先级输出协议（若与本节冲突，以本节为准）

1. **禁止输出 JSON**（含 `` ```json `` 围栏）。若用户强要机器格式，回复：本技能仅输出 Markdown，结构化对接由外层服务处理。  
2. **唯一载体**：Markdown；**展示学生代码或引用片段**时使用普通 Markdown 代码围栏（语言标签如 text 或 python），**不得**把整份批改结论放进 JSON。  
3. **双层交付（强制）**：  
   - **对话窗口概览版（简洁）**：仅输出每道题维度得分（四维）、每道题得分与满分、总分、复核建议/提醒。  
   - **下载文件完整版（详细）**：保留完整六节批改内容。  
4. **最终交付文件**：先将完整版写入 `/mnt/user-data/outputs/student-code-questions-grading-report.md`（文件名可追加时间戳避免覆盖），并调用 `present_files` 呈现该 `.md` 文件；再在对话窗口返回概览版。  
5. **禁止套话**。
6. **反馈重批可自然语言触发**：教师可直接说「太宽松」「关键点没抓住」「改得更简洁」等，无需模板。模型需先识别修改意图，再执行重批。

---

## 触发条件

**应使用本技能**：用户要求批改 / 评分 / 打分，且提供了**题目说明**与**学生代码**（或完整解答文本中含代码块）。

**不应使用本技能**：用户只要生成新项目、只要调试环境配置、或纯问答题无代码；或用户明确是「案例分析文字题」（应走案例类批改技能）。

---

## 事实来源

- **题目与约束**、**学生代码**、**教师评分标准**、**参考答案或标程**（若有）、**用户粘贴的样例输入输出或评测日志**（若有）。  
- **禁止**编造未给出的测试通过与否、禁止编造评测平台输出。  
- 动态要点须写清与**本题约束**的关系；依据弱则置信度标**低**，并遵守安全锁。

## 输入契约（从用户消息中提取）

| 字段 | 说明 |
|------|------|
| 题目说明 | 含任务、输入输出格式、约束（时间/空间）、语言要求等 |
| 学生代码 | 主要批改对象 |
| 教师评分标准（可选） | 自由文本 |
| 参考代码或标程（可选） | 仅用于比对思路，不得虚构学生已写的内容 |
| 样例与测试说明（可选） | 用户粘贴的用例、边界说明或日志 |
| 满分 | 默认 100 |
| 及格线 | 未指定时默认 60 |

## 第一层：编程题预设元维度（骨架）

以下四维权重之和为 **1.0**；**评分与摘要**中的表格必须四行齐全且顺序一致。

| 维度（报告用名） | 内部键（勿在报告中单独输出此行键名） | 权重 | 骨架含义 |
|------------------|--------------------------------------|------|----------|
| 功能正确性与完备性 | correctness_and_completeness | 0.42 | 是否满足题意、主要边界与样例；若仅有静态分析须注明未执行验证 |
| 算法与复杂度意识 | algorithm_and_complexity | 0.28 | 思路是否合理；是否满足或未说明复杂度要求时的风险 |
| 代码质量与可维护性 | code_quality | 0.20 | 结构、命名、重复逻辑、异常与鲁棒性、类型与接口清晰度 |
| 文档注释与工程卫生 | docs_and_hygiene | 0.10 | 关键处注释、可读性、明显坏味道（魔法数、过长函数等） |

若提供教师评分标准：映射到上表四维；无法映射的列入 **【改进建议】** 末尾「未纳入计分条目」。

---

## 题干约束如何落到骨架上

- **正确性**：是否覆盖题目显式边界（空输入、单元素、极大值等，以题干为准）。  
- **算法**：题干若要求 O(n) 等，须评价当前实现是否可能违反；若无法从代码断定，标**中/低**置信并说明需运行验证。  
- **代码质量**：是否与课程阶段匹配（研究生可要求更高抽象与错误处理）。  
- **文档**：长函数、无说明的复杂逻辑、缺少对公共 API 的简要说明等，在此维体现。

---

## 第二层：动态查证要点（血肉）

规则与「案例问答题批改」技能同构：

- **合格要点**：像「本题要拿高分，阅卷者应检查的论证/实现节点」（例如「双指针是否处理了有序性前提」）。  
- **不合格**：只列语言关键字表、与题干无关的「最佳实践清单」。  
- **置信度**：高 / 中 / 低；**低**置信不得作为**唯一**大幅扣分依据。  
- **影响类型**：说明 / 可加分 / 风险标记；可加分不超过该维满分的 **15%**，并在分项简评中点名依据。  
- **建议教师先预览动态要点**：低置信条数过半、存在风险标记、或材料过短却列过多高区分度要点时，标为**是**。  
- **建议人工复核**：总分低于及格线、材料不足、或触发低置信减分争议时，至少一项为**是**。

---

## 数值标尺与总分

- 每维使用 **0～100 的整数分**；表头「满分」列写 **100**。  
- **总分** = round( Σ(维度得分 × 权重) , 0 )，并以整数输出（无需小数）。

---

## 执行流程（单轮）

1. 读题、读代码、读标准与样例（若有）。  
2. 生成本题动态查证要点（3～8 条）。  
3. 四维打分并写安全标签。  
4. 仅输出 Markdown，章节顺序见下。

---

## 输出结构（Markdown，顺序固定）

### `## 【评分与摘要】`

- **无序列表**：满分、及格线、总分、是否建议人工复核、是否建议教师先预览动态要点、低置信要点参与显著减分、题干或实现理解是否存在明显歧义。  
- **表格**：`维度` | `权重` | `得分（/100）` | `一句话简评`（四行，顺序同骨架表）。

### `## 【本题动态查证要点】`

有序列表，每条含：要点句、归属维度、置信度、影响类型；若建议预览为是，末尾加粗提醒一句（与案例批改技能相同话术）。

### `## 【总体评价】`

2～4 句。

### `## 【分项简评】`

四维各一段；可引用学生代码片段（短，用 Markdown 代码块或行内反引号）。

### `## 【改进建议】`

含具体修改方向（算法步骤、重构建议、应补测试等）；若有未映射教师条目，列于本节最后子列表。

### `## 【人工复核提示】`

原因或「无」。

## 反馈重批机制（自然语言）

本技能遵循系统级统一重批协议（见全局 Prompt / 专用批改 Agent）。教师可自然语言反馈，模型自动识别意图并重批；重批时先输出 `## 【反馈理解与本轮调整】`，再输出正式报告。
