# Grading Skills — Common Protocol

本文件定义了所有 `student-*-grading` 技能的**共享协议**。各技能的 SKILL.md 通过引用本文件来避免重复。
当需要修改通用行为时，只需编辑本文件一处。

---

## 1. 通用 read_file 硬规则

批改任务下：

1. **仅允许** `read_file` 本技能 `SKILL.md` 文件。
2. **禁止** 为完成批改而 `read_file` 任何其他技能目录下的 `SKILL.md`。
3. **禁止** 用 `glob` / `grep` 在 `/mnt/skills/public/` 下搜索关键词来"挑文件"。
4. **唯一例外**：反馈重批场景允许额外读取 `student-grading-feedback-revision/SKILL.md` 一次。
5. 若已误读其它文件：最终输出前**忽略**其内容，仅按本技能文件与用户消息重新组织批改结论。

---

## 2. 通用输出协议

### 2.1 禁止 JSON
最终回复中**不得**出现任何 JSON 对象，也**不得**使用 `` ```json `` 代码块承载分数。全部结论使用 **Markdown**。

### 2.2 双层交付（强制）
1. **对话窗口概览版（简洁）**：维度得分 + 每题得分与满分 + 总分 + 复核建议。
2. **下载文件完整版（详细）**：完整的六节批改内容（见 §3）。
3. 先生成完整版写入 `/mnt/user-data/outputs/<技能名>-grading-report.md`，调用 `present_files` 呈现；再在对话窗口返回概览版。

### 2.3 禁止套话
不要输出与批改无关的前后缀或思考独白。

---

## 3. 六节输出结构（顺序固定）

每一份完整批改报告必须按以下顺序包含六个章节：

| # | 章节标题 | 内容要点 |
|---|---------|---------|
| 1 | `## 【评分与摘要】` | 无序列表（满分/及格线/总分/复核建议/预览建议/低置信减分/歧义）+ 四维表 |
| 2 | `## 【本题动态查证要点】` | 有序列表，每条含：要点→归属维度→置信度→影响类型 |
| 3 | `## 【总体评价】` | 2～4 句概括水平与主要问题 |
| 4 | `## 【分项简评】` | 四维各一段，可引用学生原文 |
| 5 | `## 【改进建议】` | 3～6 条可执行建议 |
| 6 | `## 【人工复核提示】` | 具体原因或"无" |

---

## 4. 第二层：动态查证要点（通用规则）

### 合格要点
每条应像**「本题若要拿高分，阅卷者应关注的论证/实现节点」**。
**不合格**：仅列出关键词或名词而无本题语境。

### 置信度（三档）
| 等级 | 适用条件 |
|------|---------|
| 高 | 要点直接对应题干明确指令，或材料中显式事实 |
| 中 | 合理推理延伸；或主要依据教师标准/参考答案 |
| 低 | 弱联想、题干可能有歧义、材料不足以区分必答与加分 |

### 影响类型（三档）
- **说明**：仅用于解释与改进建议，不作为减分唯一理由。
- **可加分**：高水平增量；加分不得超过该维满分（100）的 **15%**。
- **风险标记**：题干理解或评分边界可能有歧义。

### 减分纪律（安全锁）
- **禁止**仅因学生未命中某条**低**置信要点而做唯一大幅扣分。
- 若扣分主要依赖**低**置信要点：「建议人工复核」必须为**是**。

### 「建议教师先预览动态要点」触发条件（满足任一）
- 低置信条数 ≥ ceil(总条数/2)
- 任一条影响类型为**风险标记**
- 题干材料过短却仍列出多条高区分度要点

---

## 5. 数值标尺与总分

- 每一维得分：**0～100 的整数分**；表中「满分」列恒写 **100**。
- **总分** = round( Σ(维度得分 × 权重) , 0 )，其中 Σ 对四维求和，以整数输出。
- 自检：四维均为 50 分 → 总分 50；四维均为 100 → 总分 100。
- 满分默认 100，及格线默认 60。

---

## 6. 通用执行流程（单轮）

1. 提取题目、学生答案、教师标准与参考（若有）。
2. 生成本题动态查证要点（3～8 条）。
3. 按四维打分；计算总分与安全标签。
4. 按 §3 输出六节 Markdown 报告。

---

## 7. 质量守卫（输出前内心自检）

- [ ] 未出现任何 JSON 或 `` ```json `` 块。
- [ ] 维度表四行齐全，权重和为 1.0。
- [ ] 各维得分在 0～100 且为整数；总分与公式一致。
- [ ] 动态要点无「纯关键词表」式内容。
- [ ] 六节标题齐全、顺序正确。
- [ ] 未 read_file 无关技能的 SKILL.md。
- [ ] 未捏造未给出的运行/评测结果（仅限编程题）。
- [ ] 未编造未提供的查重率或引用来源（仅限论文批改）。

---

## 8. 反馈重批机制（统一协议）

### 8.1 自然语言触发
教师可直接给出口语化修改意见（如「太松」「重点偏了」「更简洁」「只改建议部分」），**无需模板**。模型须先识别意图再执行重批。

### 8.2 意图识别分类
1. 评分强度（更严格/更宽松）
2. 关键点纠偏（漏判/误判/偏题）
3. 风格要求（更简洁/更学术/更面向学生）
4. 结构调整（先结论、建议更具体、减少冗余）
5. 局部重写（只改某一节或某一维）
6. 结论偏好（复核建议倾向、通过风险口径）
7. 证据要求（依据不足、需更多原文引用、避免臆测）

### 8.3 意图到改动范围映射
| 意图 | 默认改动范围 |
|------|--------------|
| 风格/结构 | 仅改表达与结构，不改分数 |
| 关键点纠偏 | 重写要点与相关分项简评，必要时重算相关维度与总分 |
| 评分强度 | 调整扣分力度并重算相关维度与总分 |
| 局部重写 | 仅改指定模块；除非明确要求，否则不改未点名模块 |
| 结论偏好 | 调整复核提示与风险标记；如影响评分标准则联动重算 |
| 证据要求 | 增补证据引用与依据说明，不得新增虚构事实 |

### 8.4 歧义处理
- 默认直接执行重批，不要求模板。
- 仅在"反馈冲突且将显著改变分数"时，最多追问 1 个澄清问题。
- 未澄清前，不进行大幅分数跳变。

### 8.5 多轮稳定性约束
1. **事实锚定**：题目事实、学生答案事实、已有证据不变。
2. **改动可追踪**：明确写出本轮改了什么、为何改。
3. **控制漂移**：未被点名模块尽量不改。

### 8.6 重批输出格式
1. 先输出：`## 【反馈理解与本轮调整】`（意图 + 改动范围 + 是否重算分数）
2. 再输出完整的六节正式报告（见 §3）。
3. 若分数变化，补一句"与上一版相比为何变化"。

### 8.7 可读性与完整度下限
- 重批版默认是"完整新版报告"，六节保留，信息密度不降低。
- 除非教师明确要求"只返回改动点"，否则不得省略正文段落。

---

## 9. 事实来源规则

- **唯一事实来源**：用户消息中的题目、案例材料、学生答案、教师评分标准（若有）、参考答案（若有）。
- **禁止**编造判决、数据、法条、论文结论或用户未提供的引用。
- 动态查证要点只能写"从题干/材料**可合理推出**的考察角度"；若依据弱，置信度必须标**低**，且遵守安全锁（§4）。
