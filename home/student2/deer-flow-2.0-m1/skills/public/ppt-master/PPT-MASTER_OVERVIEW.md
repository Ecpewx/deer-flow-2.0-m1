# PPT Master — AI 驱动的智能演示文稿生成系统

> 本文档旨在向技术评审老师介绍 PPT Master 系统的核心能力、技术架构与工作流程。

---

## 一、系统概述

**PPT Master** 是一个基于 AI 多角色协作的智能演示文稿生成系统。它能够将用户的源文档（PDF、DOCX、网页链接、Markdown）自动转化为**原生可编辑的 PPTX 文件**（基于 DrawingML 标准，非图片式 PPT）。

### 核心价值

| 特性 | 说明 |
|------|------|
| 🎯 **原生可编辑** | 生成的 PPTX 使用 PowerPoint 原生形状（Shape/TextBox/Chart），可在 PowerPoint/WPS 中任意编辑 |
| 🧠 **AI 驱动** | 多角色 AI 协作（策略师 → 图片生成 → 执行器），无需人工设计 |
| 📐 **多画布格式** | 支持 16:9、4:3、小红书、微信朋友圈、Story 等多种格式 |
| 🎨 **21 套专业模板** | 内置 McKinsey、Google、Anthropic、政府红蓝、学术答辩等模板 |
| 🔌 **零依赖核心** | 大部分工具仅依赖 Python 标准库，可选依赖按需安装 |

## 二、技术架构

### 2.1 整体流程

```
源文档 → 创建项目 → 模板选择 → 策略师八项确认 → [图片生成] → 执行器生成SVG → 后处理 → 导出PPTX
```

### 2.2 多角色协作模型

系统采用 **四角色流水线架构**，每个角色独立且串行执行：

```
┌─────────────┐    ┌─────────────┐    ┌───────────────┐    ┌─────────────┐
│  策略师      │ →  │  图片生成器  │ →  │   执行器      │ →  │   后处理     │
│ (Strategist) │    │ (Img_Gen)   │    │  (Executor)   │    │ (Pipeline)  │
├─────────────┤    ├─────────────┤    ├───────────────┤    ├─────────────┤
│ • 八项确认   │    │ • AI 生图   │    │ • SVG 逐页生成 │    │ • 笔记拆分   │
│ • 设计规范   │    │ • 图片分析   │    │ • 演讲备注     │    │ • SVG 优化   │
│ • 锁定文件   │    │             │    │ • 跨页一致性   │    │ • PPTX 导出  │
└─────────────┘    └─────────────┘    └───────────────┘    └─────────────┘
```

### 2.3 技术栈

| 层级 | 技术 |
|------|------|
| **SVG 生成** | 纯手工 SVG (viewBox 坐标系统) |
| **PPTX 导出** | python-pptx + DrawingML (原生形状) |
| **源文档转换** | PyMuPDF(PDF) / mammoth(DOCX) / markdownify(HTML) / curl_cffi(网页) |
| **图片生成** | 多后端支持: Gemini / OpenAI / SiliconFlow / 智谱 / Minimax 等 12+ 平台 |
| **图标库** | 6700+ 内置矢量图标 (Tabler Icons 三套风格) |
| **图表模板** | 50+ 可视化图表 SVG 模板 |

## 三、核心功能详解

### 3.1 源文档处理

支持多种输入格式并自动转换为 Markdown：

| 输入类型 | 转换工具 | 输出 |
|---------|---------|------|
| 📄 PDF | `pdf_to_md.py` (PyMuPDF) | Markdown + 图片提取 |
| 📝 DOCX/Word | `doc_to_md.py` (mammoth) | Markdown |
| 📊 PPTX | `ppt_to_md.py` | Markdown |
| 🌐 网页链接 | `web_to_md.py` (requests/curl_cffi) | Markdown |
| 📱 微信公众号链接 | `web_to_md.py` (curl_cffi TLS 指纹伪装) | Markdown |

### 3.2 项目管理器

提供完整的项目生命周期管理：

```bash
# 创建项目
project_manager.py init <项目名> --format ppt169 --dir /mnt/user-data/projects

# 导入源文件（自动转换 PDF/DOCX 为 Markdown）
project_manager.py import-sources <项目路径> <源文件...> --move

# 验证项目结构
project_manager.py validate <项目路径>
```

**项目目录结构：**
```
my_project_ppt169_20250418/
├── sources/          # 源文件 & 转换后的 Markdown
├── svg_output/       # 执行器生成的原始 SVG
├── svg_final/        # 后处理优化后的 SVG
├── images/           # 图片资源
├── notes/            # 演讲备注
├── templates/        # 选中模板文件
├── exports/          # 最终导出的 PPTX
├── design_spec.md    # 设计规范（人类可读）
└── spec_lock.md      # 执行锁定文件（机器可读）
```

### 3.3 模板系统

内置 **21 套专业模板**，覆盖多种场景：

| 类别 | 模板 | 适用场景 |
|------|------|---------|
| 🏢 **品牌风格** | Google Style, McKinsey, Anthropic, 中国电信, 招商银行 | 企业级演示 |
| 🎯 **通用风格** | Exhibit, 科技蓝商务, Smart Red | 日常商务 |
| 🎓 **学术场景** | 学术答辩, 重庆大学, 医学院 | 论文答辩/学术报告 |
| 🏛️ **政府风格** | 政府红, 政府蓝, AI Ops | 政务汇报 |
| 🎮 **创意风格** | Pixel Retro | 技术分享/创意 |

**自由设计模式**：大多数场景推荐 AI 自由设计，根据内容量身定制结构和风格。

### 3.4 策略师阶段（八项确认）

这是系统的核心决策环节，AI 策略师与用户进行 **八项确认**，确保设计方向符合需求：

1. ✅ **画布格式** — 16:9 / 4:3 / 小红书 / 朋友圈
2. ✅ **页数范围** — 建议页数
3. ✅ **目标受众** — 谁来看这个 PPT
4. ✅ **风格目标** — 专业/科技/温暖/权威
5. ✅ **配色方案** — 主色/辅色/背景色系统
6. ✅ **图标使用** — 图标风格与密度
7. ✅ **字体排版** — 中英文字体搭配
8. ✅ **图片使用** — AI 生成/现有图片/占位符

确认后自动生成：
- **`design_spec.md`** — 人类可读的设计叙事文档（11 个章节）
- **`spec_lock.md`** — 机器可读的执行锁定文件（执行器每页重新读取，防止长文上下文漂移）

### 3.5 执行器阶段（SVG 生成）

这是技术含量最高的核心环节：

- **纯手工 SVG 绘制**：所有页面使用标准 SVG 绘制，遵循严格的 viewBox 坐标系统
- **逐页连续生成**：确认全局参数后，逐页连续生成，保证跨页一致性
- **每页重读锁定文件**：生成每页 SVG 前重新读取 `spec_lock.md`，防止上下文压缩漂移
- **多风格执行器**：支持 General / Consultant / Top Consultant 三种风格模式

**SVG 技术约束**（确保 PPTX 兼容性）：
- ❌ 禁止: `mask`, `<style>`, `class`, `foreignObject`, `textPath`, `rgba()`
- ✅ 使用: `fill-opacity`, 内联样式, `<tspan>` 文本换行
- ⚡ 条件允许: `clipPath`(仅用于图片)、`marker`(箭头)

### 3.6 后处理与导出

三步骤串行流水线，每个命令完成后确认再执行下一个：

| 步骤 | 工具 | 功能 |
|------|------|------|
| 1️⃣ | `total_md_split.py` | 拆分演讲备注到各页面 |
| 2️⃣ | `finalize_svg.py` | SVG 后处理：图标嵌入、图片裁剪嵌入、文本展平、圆角矩形转路径 |
| 3️⃣ | `svg_to_pptx.py` | **最终导出 PPTX**（⚠️ 必须通过工具调用执行）|

**导出产物：**
- `<项目名>_<时间戳>.pptx` — 原生 DrawingML 形状（可在 PowerPoint 中编辑）
- `<项目名>_<时间戳>_svg.pptx` — SVG 引用版本

## 四、关键设计原则

### 4.1 严格串行执行

```
步1 → 步2 → 步3 → ... → 步7
```

- 每一步的输入是上一步的输出
- 禁止跨步骤批处理、并行执行
- "阻塞点"（模板选择、八项确认）必须等待用户明确确认

### 4.2 跨页一致性保障

- **`spec_lock.md` 机制**：执行器在生成每个 SVG 页面之前都重新读取该文件
- 所有颜色、字体、图标、图片来源必须来自锁定文件
- 防止在长文档生成过程中发生上下文压缩导致的风格漂移

### 4.3 最终导出必须调用工具

> ⚠️ **重要**：最后一步 PPTX 导出（`svg_to_pptx.py`）**必须通过 Tool Call 方式执行**，不能手动在终端运行。导出完成后通过工具返回生成的 PPTX 文件路径和结果信息。

## 八、快速开始

```bash
# 1. 转换源文档为 Markdown
python3 pdf_to_md.py source.pdf

# 2. 创建项目
python3 project_manager.py init my_ppt --format ppt169 --dir /mnt/user-data/projects

# 3. 导入源文件
python3 project_manager.py import-sources /path/to/project source.md --move

# 4. 选择模板 / 自由设计 → 策略师八项确认 → 执行器生成 SVG → 后处理 → 导出 PPTX
```
