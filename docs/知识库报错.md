# DeerFlow 集成本地课程知识库方案说明

> 作者：deer-flow-team  
> 日期：2026-04-26  
> 目标：让 DeerFlow Agent 能够从本地 Chroma 课程知识库中检索资料，替代对 RAGFlow MCP 的依赖

---

## 背景

DeerFlow 需要访问课程教学资料（PPT、教材、案例等）来回答用户问题。最初尝试通过 RAGFlow MCP 协议接入知识库，但由于 MCP 认证问题（401 Unauthorized）一直未能打通。因此转向方案二：**将已有本地 ChromaDB 知识库挂载到 DeerFlow 容器，通过自定义 Tool 直接查询**。

## 已完成的步骤

### 1. ChromaDB 挂载到容器

**文件修改：** `docker/docker-compose.yaml`（生产环境）

在 `langgraph` 服务的 `volumes` 中添加：

```yaml
- ${HOME}/zjl/zufe/edu-agent-system/db/chroma:/app/chroma_db:ro
```

通过 `ro`（只读）挂载，防止容器意外修改宿主知识库。

### 2. 安装 ChromaDB 到容器

```bash
# 注意：只能用 uv，不能用 pip，因为 .venv/ 里没有 pip
docker exec deer-flow-langgraph sh -c "cd /app/backend && uv pip install --python .venv/bin/python3 chromadb"
```

验证安装：
```bash
docker exec deer-flow-langgraph sh -c "cd /app/backend && .venv/bin/python3 -c 'import chromadb; print(chromadb.__version__)'"
# 输出: chromadb 1.5.8
```

### 3. 创建自定义 Tool

**文件：** `backend/packages/harness/deerflow/community/chroma_kb/__init__.py`
**文件：** `backend/packages/harness/deerflow/community/chroma_kb/tools.py`

Tool 的核心逻辑：
1. 获取用户 query
2. 通过 SiliconFlow API（`Qwen/Qwen3-Embedding-4B`）计算 query embedding
3. 用 `query_embeddings` 参数查询 ChromaDB
4. 格式化返回结果

### 4. 注册为 Builtin Tool

**文件修改：** `backend/packages/harness/deerflow/tools/tools.py`

```python
from deerflow.community.chroma_kb.tools import chroma_retrieve

BUILTIN_TOOLS = [
    present_file_tool,
    ask_clarification_tool,
    chroma_retrieve,
]
```

## 当前问题（阻塞）

### 问题 1：Chroma 查询返回空结果

**现象：** Agent 调用了 `chroma_retrieve` 工具，但返回"知识库中未找到相关内容"。

**原因分析：**
- ChromaDB 的 `query_texts=[query]` 使用默认 embedding function（`all-MiniLM-L6-v2`）
- 但知识库中的向量是用 **`Qwen/Qwen3-Embedding-4B`**（通过 SiliconFlow API）预计算的
- 语义空间不匹配，导致查询无结果或报错

**已尝试的修复：**
- [x] 改用 `query_embeddings=[query_embedding]`，自行通过 SiliconFlow API 计算 query 向量
- [ ] 需要重启验证修复是否生效

### 问题 2：RAGFlow MCP 认证失败（备选方案）

**现象：** MCP Server 返回 401 Unauthorized

**原因分析：**
- DeerFlow 通过 `langchain-mcp-adapters` 连接 RAGFlow MCP SSE endpoint
- RAGFlow MCP 在 `self-host` 模式下，API Key 是给**服务内部**调用 RAGFlow REST API 用的
- 但 DeerFlow 在 SSE 连接时未正确携带认证头，导致 `langchain-mcp-adapters` 报 401
- 尝试在 `extensions_config.json` 中添加 `headers` 字段传递 API Key，未解决

## 下一步改进方向

### 方向 A：继续修复 Chroma 方案（推荐）

1. **重启验证最新代码**
   ```bash
   sudo make down && sudo make up
   docker logs deer-flow-langgraph 2>&1 | grep -i "chroma\|embedding\|compute"
   ```
   如果还不行，检查：
   - SiliconFlow API 调用是否成功（网络、API Key）
   - Chroma collection 名称是否完全匹配（`course_material_chunks`）

2. **离线 Embedding 方案**（可选）
   如果每次查知识库都要调 SiliconFlow API 比较慢，可以考虑：
   - 在容器中装 `sentence-transformers` 加一个轻量模型（如 `BAAI/bge-small-zh-v1.5`）
   - 或者建一个本地的 Embedding 服务

3. **改善 Tool 描述**
   当前 Tool description 已标记为"【重要优先】"，但 LLM 仍可能优先选用 `web_search`。可进一步：
   - 在 System Prompt 或 Skills 中写规则：教学/课程类问题先用 `chroma_retrieve`
   - 或者限制 `web_search` 在课程相关问题上的使用

### 方向 B：继续排查 RAGFlow MCP（备选）

如果在 MCP 方案上有突破，可以参考：

1. **确认 RAGFlow MCP 模式**
   - 当前以 `self-host` 模式启动，API Key 用于服务内部调用
   - MCP 客户端（DeerFlow）不需要传 API Key
   - 401 可能来自 RAGFlow 内部 API（9380 端口）拒绝提供的 API Key

2. **改用 Streamable HTTP 协议**
   - RAGFlow MCP 同时支持 SSE 和 Streamable HTTP
   - `POST /mcp` 端点可能比 SSE 更适合
   - 在 `extensions_config.json` 中设置 `"type": "http"`

3. **检查 RAGFlow 容器日志**
   ```bash
   docker logs docker-ragflow-cpu-1 2>&1 | grep -i "401\|mcp\|unauthorized"
   ```

### 方向 C：使用 Skill 机制指导 Agent 行为

DeerFlow 支持 Skills 机制，可以创建一个 Skill 来告诉 Agent：
- 哪些场景应该优先使用 `chroma_retrieve`
- 知识库中包含了什么课程
- 如何组合知识库查询 + 网络搜索得到更好的回答
