# 导师推荐技能

## 使用场景
- 用户表达导师选择、导师推荐、研究方向匹配、读研导师咨询等诉求时触发。
- 默认从 `data/zufe_mentors.json` 做检索，输出 Top5 导师候选。
- 用户**必须先提供专业**（例如：图书情报、电子信息、管理科学与工程）；未提供专业时禁止直接推荐。

## 数据来源
- 主数据：`data/zufe_mentors.json`
- 检索脚本：`scripts/mentor_retrieval.py`
- 推荐过程必须仅基于上述本地 JSON 数据；禁止调用网络搜索、网页抓取或任何外部在线数据源。

## 数据结构兼容规则
本技能兼容两类导师主页来源：

1) `https://person.zufe.edu.cn`  
读取 `url_details` 中：
- 个人信息
- 基本信息
- 科学研究
- 教学研究
- 招生与就业

2) `https://info.zufe.edu.cn/szdw/fjs/`（或同域师资页）  
读取 `url_details` 中：
- 个人信息
- 个人简介
- 教学与育人
- 论文与专著
- 课题与社会服务
- 奖励与荣誉

## 检索方式
- 混合检索：`BM25 + 向量余弦重排`
- 向量部分采用文本 n-gram 的 TF-IDF 表征做余弦相似度。
- `must-have` 为软偏好加分项（重排优先，不做硬过滤）。
- 若满足条件人数不足 5 人，则**全部返回**（不强凑 5 人）。
- 检索顺序固定为：**先按专业筛出全量相关导师** → 再在该专业集合内做混合排序与约束过滤。
- “按专业筛选”以导师条目的 `program` 归属为准（确保推荐结果属于该专业导师池）。
- 当用户仅提供专业时，需提高“研究方向/论文与专著/课题与社会服务/近期成果”等学术信号权重后再排序。
- 当用户仅提供专业时，近三年（当前按 2024-2026）科研/论文/项目证据权重需高于其他年份信息。
- 当用户仅提供专业时，若导师在“科学研究/论文与专著/课题与社会服务”中缺少近三年证据，应显著降权。
- 当用户仅提供专业时，若存在“近三年有科研/论文/项目证据”的导师集合，应仅在该集合内排序；仅当该集合为空时才回退到全量专业导师池。
- 当用户仅提供专业时，排序主键应为“近三年产出数量”从高到低；同数量时再按综合相关度排序。
- 性别偏好中的“未提供性别”作为兜底并入：
  - 若要求男老师：返回 男 + 未提供；
  - 若不要男老师：返回 女 + 未提供（其他性别偏好同理）。

## 调用方式

### 优先路径（无 bash 环境，推荐）
- 如果当前会话没有 `bash` 工具，**禁止**尝试执行命令行。
- 直接读取：
  - `data/zufe_mentors.json`（导师原始数据）
  - `scripts/mentor_retrieval.py`（检索规则与字段映射）
- 按脚本同等逻辑在会话内完成检索与排序：
  1) 文本分词与归一化  
  2) BM25 关键词召回  
  3) TF-IDF 向量余弦重排  
  4) 应用 `must-have` / `avoid` 约束  
  5) 输出 Top5（默认）并附匹配依据

### 可选路径（有 bash 工具时）
```bash
python skills/public/mentor-recommendation/scripts/mentor_retrieval.py \
  --major "电子信息" \
  --query "我想找人工智能方向、有产业项目、偏应用的导师" \
  --top-k 5 \
  --show-similarity
```

### 多轮约束示例
```bash
python skills/public/mentor-recommendation/scripts/mentor_retrieval.py \
  --major "电子信息" \
  --query "人工智能 电子信息专硕" \
  --must-have "产业项目,应用" \
  --avoid "纯理论" \
  --top-k 5 \
  --show-similarity
```

### 参数说明
- `--research-direction-en`：研究方向英文关键词（可选，优先作为检索查询）
- `--query`：兼容旧参数（可选）
- `--major`：用户专业（必填，缺失则不推荐）
- `--history-query`：多轮历史偏好合并文本（可选）
- `--must-have`：必须偏好，逗号分隔（可选）
- `--avoid`：排除偏好，逗号分隔（可选）
- `--top-k`：返回数量，默认 5
- `--export-format`：导出格式（`auto` / `word` / `doc` / `docx` / `pdf` / `md`，可选）
- `--export-path`：导出文件路径（可选，不填则自动落到 `skills/public/mentor-recommendation/exports/`）

### 报告导出（Word / PDF）
- 默认行为：直接网页输出推荐结果，不导出文件。
- 当用户明确要求“生成 Word / DOCX / PDF 报告”时，必须调用导出参数。
- 当用户要求“生成文档”但未指定格式时，必须使用 `--export-format auto`，默认导出 Word（`.docx`）。
- 当用户明确要求 `doc` 或 `docx` 时，统一按 Word 路径导出（文件后缀为 `.docx`）。
- 当用户明确要求 `pdf` 时，必须使用 `--export-format pdf`（不回退到其他格式）。
- 导出内容必须基于当前轮“最新回答”的结果快照（专业、条件、导师详情、推荐理由），不得使用旧轮结果，不得引入外部数据。
- 无论网页输出还是导出文档，均禁止出现“排名第一/第N名/TOPN/明显优于/不如某导师”等排名、比较、拉踩词汇。
- 系统限制：若运行环境无法直接访问 `/usr/share/fonts/`，PDF 导出必须通过 Python 代码路径完成字体注册（如 `reportlab` 的 `UnicodeCIDFont("STSong-Light")`）；禁止依赖直接读取系统字体文件。
- 推荐命令示例：

```bash
python skills/public/mentor-recommendation/scripts/mentor_retrieval.py \
  --major "电子信息" \
  --query "artificial intelligence, data mining" \
  --top-k 5 \
  --export-format auto
```

```bash
python skills/public/mentor-recommendation/scripts/mentor_retrieval.py \
  --major "电子信息" \
  --query "computer vision" \
  --top-k 5 \
  --export-format pdf
```

## 防错规则（必须遵守）
- 不得在无 `bash` 工具时重复尝试命令执行。
- 若检测到工具能力受限，直接走“优先路径（无 bash）”。
- 若出现工具调用中断，优先给出当前可得的 Top5 结果，不进入循环重试。
- 若用户未提供专业，必须先追问专业，禁止直接推荐导师。
- 若用户仅提供专业、未提供偏好，也可以先返回该专业基础 Top5，再引导补充偏好做二次筛选。
- 若用户追加性别约束，必须执行“已知性别 + 未提供性别兜底”的规则，避免因字段缺失误删候选。
- 若用户在第二轮补充偏好（如“推荐女老师”），应在原专业条件上重新排序并尽量返回 Top5，不得直接删减为仅2人结果。
- 若专业无法命中，必须明确提示“未检索到该专业相关导师”，并引导用户改写专业名称。

## 专业缺失时的标准追问
请先告诉我你的专业（或报考方向），例如：图书情报、电子信息、管理科学与工程。  
导师推荐必须先基于专业筛选，再做匹配排序。

## 输出字段
- 导师姓名
- 学院 / 项目类型
- 导师主页 URL
- 匹配分数与匹配证据片段
- 推荐理由（基于命中信息自动生成的可解释摘要）

## 数据来源强约束（必须遵守）
- 除“推荐理由”外，所有展示字段都必须来自 `data/zufe_mentors.json` 的原始内容。
- 严禁模型自行补全或猜测任何事实信息（包括但不限于：性别、邮箱、职务、办公地点、招生信息、论文数量、获奖信息）。
- 若 JSON 中字段为空或缺失，必须原样标注为：`未提供`，不得编写替代内容。
- 推荐理由可以由模型生成，但必须仅基于 JSON 可见信息，不得引入外部事实。
- 严禁使用 web_search / web_fetch / 浏览器抓取 等网络能力补充导师信息。

## 最终回复格式规范（必须遵守）
- 直接在网页正文输出，不要附加“以下为 Markdown”或代码块包裹。
- 默认输出 Top5；若不足 5 人，显示“共匹配 N 人，已全部返回”。
- 无论首轮还是多轮对话中的任意一轮，最终输出都必须严格使用本文件 `推荐输出模板` 与 `严格输出骨架`，不得因轮次变化而简化。
- 结果说明必须写明：当前展示为“在目前条件下最匹配的部分候选”，不代表完整名单。
- 输出结构必须固定为：先“大表对照”→ 再“逐位导师详细信息”→ 最后“引导用户补充更多偏好”。
- 网页输出禁止给导师编号/名次/排名文案；仅按排序后的顺序展示即可。
- 禁止任何比较、拉踩、贬低性表述（例如“明显优于”“不如某导师”等）。
- 禁止输出任何“排序结论句”或“成功率排序句”（例如：`最终推荐排序（基于读博成功率）：A ≥ B > C`）。
- 禁止使用 Emoji、星级或符号对导师打分（例如：`⭐`、`★★★★★`、`S/A/B档`）。
- 相似度仅可用于内部检索/思考过程；网页最终输出禁止展示任何相似度分数或百分比。
- 每位导师信息必须包含：姓名、学院、项目类型、主页链接、统一个人信息、近期代表作、近期研究项目、学生深造去向、AI推荐理由。
- `主页` 必须是具体导师页面 URL；若仅有站点根地址（如 `https://person.zufe.edu.cn`、`https://info.zufe.edu.cn/szdw/fjs/`）则统一写 `未提供`。
- 不得只给名单，必须提供解释性信息与可比较维度。
- 禁止输出 `To-dos`、系统提示或思考过程。

### 多轮对话强约束（重点）
- 以下规则在多轮对话的每一轮都必须严格执行，不得因用户追加条件而放宽：
  - 必须声明“当前展示为在目前条件下最匹配的部分候选”（对应上文规则）。
  - 输出结构固定为“先大表对照 → 再逐位导师详细信息 → 最后引导补充偏好”。
  - 禁止编号/名次/排名文案，禁止任何比较、拉踩或贬低性表述。
  - 禁止输出任何排序结论句、成功率排序句，以及 Emoji/星级打分。

|---|---|---|---|---|---|

导师：<导师姓名>

  - 学历：...
  - 学位：...
  - 联系方式：...
  - 办公地点：...

## 严格输出骨架（不可变）
每次回复（含首轮与后续多轮）必须按以下顺序输出，且字段名完全一致：
1. 导师推荐结果（<专业>）
2. 一行汇总：共匹配 N 人（条件：...）；不足 5 人时已全部返回。
3. 一行说明：当前展示为“在目前条件下最匹配的部分候选”。
4. 导师对照表（导师/学院/项目类型/性别/研究方向/主页；不含排名列，不含相似度字段）。
5. 从 `导师：<导师名>` 开始逐人详情，且每人必须包含以下字段：
   - 主页
   - 个人信息（统一顺序：性别/学历/学位/联系方式/办公地点/所在系部/研究方向）
   - 特色亮点（可聚合：近期代表作/近期研究项目/学生深造去向/教学与育人/论文与专著/课题与社会服务/奖励与荣誉/科学研究/教学研究/招生与就业）
   - AI推荐理由
6. 最后输出“下一步建议（引导补充偏好）”。

## 回复前格式自检（每轮必做）
- 若缺少以下任一项，必须重排后再输出：
  1) 汇总行 + “部分候选”说明
  2) 导师对照表
  3) 逐位导师详情块
  4) 下一步建议
- 若出现以下任一违规，必须重写后再输出：
  - 排名/名次/比较/拉踩
  - 相似度数值外显
  - 星级/Emoji 打分
